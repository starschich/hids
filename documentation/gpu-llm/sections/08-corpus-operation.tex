MCP is a doorway for other programs, not part of retrieval. Working on the
developer VM, it is never needed. It exists so an agent on another machine ---
Hermes, say --- can use the corpus, and so a coding session can search the
documents mid-conversation.

\subsection{Known limits}

\begin{itemize}\itemsep1pt
  \item \textbf{Scanned PDFs index nothing.} Ingest flags them rather than
        silently adding empty chunks. The main model
        (\cmd{qwen3.5:122b-a10b}) has vision and is the obvious OCR path if
        needed. The dedicated vision model previously noted here,
        \cmd{qwen2.5vl:32b}, was removed once the main model superseded it.
  \item \textbf{Damage already in the source is not repaired.} The eCIGRE
        brochure list contains titles that lost their ligatures before reaching
        the spreadsheet (``Model specication''), so a search for
        ``specification'' will not match them. Ligature repair runs only for
        PDFs, where the document's own text supplies a trustworthy vocabulary.
  \item \textbf{One writer.} LanceDB is embedded: concurrent readers are fine,
        two simultaneous ingests are not.
  \item \textbf{Rerank latency.} The 120B spends reasoning tokens before any
        visible output, so a reranked query costs $\approx$20\,s.
  \item \textbf{LAN exposure.} With \cmd{-{}-host 0.0.0.0} the bearer token is
        the only thing between the office network and every indexed document.
\end{itemize}

\subsection{Backups}
\cmd{index/} and \cmd{md/} are derived --- they can be deleted and rebuilt from
the sources at any time. The pipeline code is what matters, and as
Section~\ref{sec:storage} notes \cmd{/shared} is one unmirrored NVMe, so that
directory belongs in Git, pushed elsewhere.
